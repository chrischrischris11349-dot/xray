# xray architecture

xray is a lightweight Discord client: a Tauri 2 shell (Rust over WebView2)
that runs Discord's web app with xray's own mod core injected before any of
Discord's scripts.

## Rules that don't bend

- **No code from Vencord, Equicord or Nightcord.** All three are GPL-3.0, and
  xray ships to other people with private source. Every feature is our own
  implementation. Ideas and behavior are fine to match. Code, even modified,
  is not.
- **Performance first.** Nothing in xray runs per frame or loops forever. Idle
  cost should be zero, and every plugin carries an impact rating
  (`light` / `moderate` / `heavy`) with a one-line reason.
- **Discord's page gets no Tauri commands** (`src-tauri/capabilities/main.json`).
  Anything callable from discord.com is callable by any script running there,
  Discord's own included. Add a command only if that's safe.

## Layout

```
core/                 the mod core (TypeScript, bundled by core/build.mjs)
  src/index.ts        boot: webpack hook, plugins, UI, the window.__xray handle
  src/env.ts          globals captured at document start (localStorage, logging)
  src/webpack.ts      module hook: find, waitFor, findByCode, filters
  src/patcher.ts      before / instead / after method patches with undo
  src/settings.ts     saved settings (localStorage for now)
  src/plugins/        plugin API, manager, impact rating, built-in plugins
  src/ui/             the xray panel (closed shadow root, vanilla DOM)
  test/               `npm test`: webpack hook, patcher and plugin checks under Node
src-tauri/            the shell
  src/window.rs       Discord window, core injection, link guard
  src/tray.rs         tray menu
  src/settings.rs     shell.json (tray and launch-at-login behavior)
  inject/core.js      generated by `npm run core:build`, embedded with include_str!
shell/                placeholder page Tauri needs to bundle; never shown
```

## How it boots

1. `window.rs` creates the window on `https://discord.com/app` and registers
   `inject/core.js` as an initialization script (main frame only). WebView2
   runs it before the page's own scripts on every load.
2. `index.ts` checks the host is Discord's, then:
   - traps `window.webpackChunkdiscord_app` as it's created and wraps every
     module factory (see the comments in `webpack.ts` for why the runtime's
     fallback `push` gets a wrapped *array* push);
   - starts enabled plugins, so their patches are in place before Discord's
     modules run;
   - mounts the UI once the document exists.
3. Discord's own scripts load and run as usual.

## Facts about Discord's page that shape the design

- **CSP `connect-src`** only allows Discord's own hosts. The page can't call
  your VPS directly, so server storage goes through Rust: a narrow command, or
  Rust-side sync. This is also where credentials belong.
- **CSP `script-src`** includes `'unsafe-eval'`, so source-level module
  patches (rewrite a factory's code, then evaluate it) are possible later.
- **CSP `font-src`** allows only a few hosts, so Google-hosted Geist can't load
  by URL. Options: Discord's gg sans plus Cascadia Mono (used now), or
  `new FontFace(name, bytes)` with font bytes we ship. Binary font sources
  aren't fetched, so CSP doesn't block them.
- **Discord deletes `window.localStorage`** after it boots. `env.ts` keeps the
  reference grabbed at document start.
- **Webpack ES module exports are read-only getters.** Patch the object or
  prototype a function lives on, or use a source patch.

## Plugins

```ts
definePlugin({
  id, name, description, category,
  impact: "light", impactReason: "Only runs when you send a message",
  needsReload: false,      // true if it hooks Discord's code as it loads
  enabledByDefault: true,
  start(ctx) {             // ctx.patch(...) and ctx.onStop(...) are undone automatically
  },
});
```

Plugins that work on browser APIs (WebSocket, XMLHttpRequest, fetch) don't
depend on Discord's internal names and switch on and off instantly. Fake
Deafen and Clean Links work this way. Plugins that hook Discord's modules use
`waitFor` and set `needsReload`.

## Roadmap

1. **Shell and core** (this milestone): window, tray, launch at login, single
   instance, link guard, webpack hook, patcher, plugin manager, panel, Fake
   Deafen, Clean Links.
2. **UI inside Discord**: render with Discord's own React (found through
   webpack, so no extra download). Covers the right-click user info, the
   full-profile sheet with per-server message counts, the quick-reply bubble,
   Ctrl+K search, and the Obsidian theme as CSS over Discord's variables plus
   Windows Mica behind a transparent page.
3. **Your server**: a small service on the VPS for settings sync and the
   names and avatars xray has seen, reached only through Rust.
4. **More plugins**: silent edit and delete, message logger, hidden channels,
   volume boost and the rest of the preview's list. Then a community plugin
   API and the store.
5. **Shipping**: installer, signed auto-updates, releases repo.

## Testing

- `npm test` runs the core checks under Node, with stand-ins for browser globals.
- Live: launch the exe with
  `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222`, pick
  the target whose URL is on discord.com, and call `window.__xray.diagnostics()`.
  Relaunch without the port afterwards.
